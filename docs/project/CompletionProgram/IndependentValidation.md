# ADR023 Independent Validation — integration contract

## Review remediation contract (findings2/3, before code)

Execution installation now requires an `execution` binding inside the independently
preregistered `NetworkQualificationConfig`. Legacy configs without it remain usable
for diagnostics but cannot authorize a provider. The binding records versioned
runtime, exact canonical per-action executable plans, physical egress identities
(node/interface/queue/source/destination), and physical demand identities
(source/destination node/address). Provider mappings must equal the reviewed values.
FRR canonical plans exclude only the runtime artifact's digest to avoid a cyclic
configuration↔runtime hash; that descriptor still requires separately accepted
runtime and equivalence evidence. A provider document cannot self-sign this binding.
The loaded independent config is retained in immutable installation evidence and
checked again at receiver dispatch. Policy total observation-to-transition delay
must not exceed the independently reviewed total; actuation duration is a part of
that total, never a replacement for it. No calibration is generated by these fixes.

## Execution-agent handoff (stable API)

New owner module: `app.modules.autonomy.calibration_verification`. No changes to
`safety.py` or execution providers are needed by this workstream.

```python
load_trusted_calibration(
    store: ArtifactStore,
    installation_path: str,
    *,
    expected_installation_sha256: str,
    expected_scope: CalibrationScope,
    now: float,
    trusted_preregistrations: dict[str, float],
    trusted_attesters: set[str],
    accepted_guarantee_sha256: set[str],
) -> LoadedCalibration
```

`ArtifactStore` is the existing bounded, no-symlink read-only store from
`app.modules.autonomy.artifact_io`. Missing/untrusted/expired/incomplete evidence
raises `EvidenceError` (malformed schemas raise Pydantic `ValidationError`); caller
must fail closed. There is no default installation or environment fallback.

`CalibrationScope` has **exact** `network_id`, `run_id`, `provider_id`,
`environment` (`isolated-emulation` or `physical-network`), `configuration_sha256`,
`egress_ids`, `demand_ids`, `action_ids`, `max_dt_seconds`, `max_delay_seconds`.
Lists are unique and compared as sets; all other values must match. Runtime must
also check configuration/action/horizon/delay scope before using `.calibration`.

`LoadedCalibration` contains `.calibration: TrustedCalibration`, `.scope`,
`.configuration: NetworkQualificationConfig`, `.installation_sha256`,
`.physical_qualified: bool`. Emulation is never physical
qualification. The loader independently re-evaluates every raw held-out queue
inequality; it does not trust an uploaded diagnostic report or calibrated flag.

Installation JSON (`nanfo.trusted-calibration-installation.v1`):
`scope: CalibrationScope`, `campaign: ArtifactRef`,
`calibration: TrustedCalibration`, `guarantee: ArtifactRef`.
Every `ArtifactRef` is `{path, sha256, size_bytes}` under the protected store root.
The guarantee is a typed, scoped evidence document with named physical obligations;
its digest must be in **server-owned** `accepted_guarantee_sha256`. It cannot approve
itself. This is an explicit human-reviewed guarantee boundary, not an inference
from empirical coverage. The installation digest must likewise be configured by
the operator outside the dossier. Never accept these trust arguments from requests.

`trusted_preregistrations` maps exact protocol byte SHA256 to externally recorded
registration Unix seconds. A timestamp written inside a dossier is insufficient.
`trusted_attesters` is the configured set of **attestation byte SHA256 digests** whose
operator/measurement identity and signed or protected-channel attestation have been
checked by the installing operator. Names alone are not authentication.
Hashes establish integrity, not identity; no generic signature verifier is claimed.

## Design and ownership

New Simulation qualification protocol/import/RF modules and operator scripts;
new Autonomy calibration verification modules; dedicated tests and this handoff.
No database migration, public API, event, execution provider, or training change.
RF uses the existing bias-only estimator fitted on train residuals only. A separate reference
calculation reconstructs predictions and held-out errors. Preregistered thresholds
cannot be widened on holdout. Complete capture groups are assigned before capture.
Network evaluation checks measured endpoints, arrival/service deltas, demand
attribution, old/new action transition and delay, and independent rational queue
and drift inequalities. Interval averages remain empirical, not guaranteed service.

Local acquisition will be an operator CLI recording actual timestamped measurements
and native source bytes in a new exclusive output directory. Privileged namespace/
traffic-control campaigns are reserved for parent-serialized admission. Historical
artifacts remain read-only. Physical RF survey and hardware guarantees cannot be
supplied by synthetic tests or local socket/emulation measurements.

Implementation, schema export commands, historical gap inventory, test results and
exact missing physical inputs will be recorded below as the work completes.

## Installed software and exact schemas

* `simulation/qualification_protocol.py`: bounded no-symlink imports, exact byte
  SHA256/length, external preregistration receipt, original instrument record
  reconstruction, whole-group train/holdout coverage, source/observation uniqueness,
  externally accepted attestation digests and hashed identity evidence.
* `simulation/qualification_rf.py`: the existing constrained +/-40dB bias estimator
  uses only declared train residuals. Its diagnostic report is discarded; an
  independent log-distance/finite-wall calculation reconstructs predictions and
  held-out MAE/RMSE/max/error rows. Acceptance thresholds are in the preregistered
  hashed configuration. There is no holdout optimization or automatic installation.
* `autonomy/calibration_verification{,_models}.py`: fixed **preregistered** per-action
  bounds (not fitted holdout extrema), per-demand/per-egress counters, conservation,
  arrivals, empirical service, capacity, sensor error, endpoint envelope, exact
  rational drift, old/new route transitions, elapsed delay and complete split/action
  coverage. Overlapping windows, unknown demands and incomplete sources refuse.
* `simulation/qualification_acquisition.py`: actual unprivileged UDP loopback and
  instrumented application-FIFO acquisition; per-event send/enqueue/dequeue/action
  timestamps, endpoint queues and counters, native event replay, source hash,
  exclusive fsynced output and partial-evidence preservation. It does not measure
  kernel/device queues. Local source evidence cannot be installed as physical.

Additional schema names: `rf-reading`, `network-reading`, `scope`, `local-recipe`,
`trust`. Native instrument export `nanfo.instrument-records.v1` contains
`instrument_id` and original records `{source_record_id, observed_at_unix_seconds,
measurement}`. Capture records add only `sample_id` and `instrument_id`; the importer
requires exact equality to the original measurement and timestamp and rejects
omitted/extra source records. Retain original vendor exports alongside this stream;
the installing operator reviews any instrument-specific normalization and identity.
No inference of sensor authenticity from hashes or an operator name is made.

RF coordinates are explicitly **meters, local Z-up**, matching existing RFScene.
Canonical Network scenes are Y-up and require a surveyed transform before import;
the preregistered `coordinate_registration_evidence_sha256` must be present among
raw sources. Receiver, transmitter, frame, dBm units and acquisition instrument are
bound. Physical geometry/antenna/survey accuracy remains an evidence obligation.

Network `dt_seconds` is the preregistered maximum observation horizon; actual
timestamp differences must be positive and no greater. Rates are bytes/second,
queues/errors bytes, times Unix seconds and drift bytes squared. Delay includes
the entire observation-to-completed-transition interval, including pre-dispatch
waiting. Bounds must cover old and new action intervals, not just settled traffic.
Required directed transitions must occur in both train and holdout. A group is a
session/run/site, not a row; real independence is an explicit operator attestation
obligation and is not statistically established by labels.

### Receiver integration requirements

In addition to `SafetyShield` and existing runtime authorization/freshness gates,
call the loaded record's guard under the dispatch lock:

```python
loaded.validate_action(
    selected_action,
    configuration_sha256=current_server_configuration_sha256,
    route_egress_ids=server_policy_route_to_ordered_egress_chain,
    previous_action_id=verified_current_action_id,
    now=now,
)
```

This requires exact reviewed per-action arrival/service/error profiles and ordered
demand-route egress chains, exact run/provider/calibration, validity, horizon and
delay scope. Keep `.configuration` and `.scope` with `.calibration`; passing only
the latter loses reviewed action/configuration constraints. The guarantee must
cover every admitted horizon up to `max_dt_seconds`, delay up to its maximum and
  all listed actions, with full demand/egress coverage. Receiver still owns capacity
readback, policy matching, observation binding, authentication, certificate expiry,
STOP/revocation, exclusion, dispatch and recovery. A loaded record is not authority
to execute, and `physical_qualified` is a scoped reviewed-evidence claim, not a
mathematical inference from finite measurements. No production installation is
created by this workstream.

1. Create an exclusive preregistration candidate:


2. Review protocol/configuration/recipe, pin exact protocol hash and receipt time

   and fresh holdout. The software cannot prove preregistration without that external

3. Use returned protocol SHA256/size and external receipt time:

   ```bash

     --root /tmp/opencode/new-independent-protocol --protocol protocol.json \

     --output /tmp/opencode/new-independent-capture
   poetry run python -m scripts.acquire_independent_validation --inspect-local \
     --root /tmp/opencode/new-independent-capture
   ```

   New loopback sockets only; max300s, 1000 windows and bounded packets. All windows,
   including incomplete captures or inequality failures, stay in the output.
   `--inspect-local` independently replays events but deliberately does not confer
   trusted status. The prepared broad no-service bounds and positive drift budget
   are diagnostic only, not a zero-drift safety certificate or enforced traffic cap.
4. Review original records and instrument identity; produce the exact attestation
   schema, its identity-evidence reference and campaign manifest. Keep all reference
   paths relative to one protected store root (use subdirectories for capture and
   protocol sources). Pin the reviewed attestation digest in a separate operator
   trust file `{trusted_preregistrations:{SHA256:TIME},trusted_attesters:[ATTESTATION_SHA256]}`.
   The tool never invents a human signature/attestation or sets an installation flag.
5. Evaluate with `qualify_independent_validation --root ROOT --manifest MANIFEST
   --manifest-sha256 SHA256 --manifest-size SIZE --trust-root PROTECTED_ROOT
   --trust TRUST_FILE`. Exit0 means empirical preregistered checks passed, not
   physical qualification; refusal/failure is exit2. RF instrument imports follow
   the same protocol. No radio sensor is simulated as a real survey.
6. Trusted installation additionally requires all eight hashed reviewed guarantee
   obligations, exact accepted environment/scope, calibration minima no smaller
   than campaign errors/uncertainty, and a protected pinned installation digest.
   Synthetic campaigns always refuse installation; emulation always returns
   `physical_qualified=false` even when explicitly accepted for that local scope.

## Controlled deterministic EMULATION continuation (2026-09-20)

### Decision: conditional FIFO theorem demonstrated; current receiver installation blocked

Read the FRR continuation, native `autonomous_causal` acquisition, runtime binding,
and review findings2/3 (executable plan equivalence and total-delay mismatch).
Execution agent owns those calibration/model/adapter corrections. This continuation
changes only new independent Simulation campaign/replay modules, an operator CLI,
its tests and this document; it does not modify the ongoing execution trust fixes.

An actual finite FIFO **can** have deterministic, non-empirical bounds in its exact
controlled scope. Implemented runtime: `isolated-controlled-sealed-fifo/v1`.
This is deliberately a *sealed observation epoch*, not an arbitrary open-arrival
fluid network. Each window first receives16 actual128-byte UDP datagrams through
fresh owned loopback sockets, records payload hashes and timestamps, then closes
both sockets before constructing the measured2048-byte finite application FIFO.
During the epoch the single owner can only select the dequeue interval or dequeue
a packet. There is no enqueue operation. Payload/FIFO ordering and finite capacity
are enforced, and the old outstanding service deadline persists across actions.

The preregistered plan maps every train/holdout old→new action to the exact operation
`set_dequeue_interval`, exact queue ID and interval. `fast=5ms`, `slow=20ms`;
the acquisition is100ms with requested transition after25ms. The independent replay
checks exact source/runtime/plan mapping, closed-ingress ordering, all payloads,
queue conservation, service pacing, observed transition and complete group coverage.
Independent means separate verification logic—not independent human attestation or
an independently implemented physical sensor.

**Proof, not empirical fitting:** for any elapsed time in the sealed epoch,
`A=0`, actual service is nonnegative, and no operation increases the queue. Thus
`0 <= q(t) <= q0 <= B`, and `V(q(t))-V(q0) <= 0`. ADR012's conditional expression
with `arrival_upper=0`, `service_lower=0`, `error=0` gives `U=q0` and upper drift0.
The finite buffer is `B=2048 bytes`, chosen before acquisition. Dequeue pacing gives
the conservative service *upper* bound `packet_bytes * (1 + floor(dt/min_interval))`;
**no positive wall-clock service lower bound is claimed**. Scheduler stalls preserve
this queue theorem. Reopening ingress, refilling/resetting, changing ownership/code,
or an unobserved mutation ends its scope and requires a fresh sealed observation.

A general-purpose Python/Linux scheduler also cannot guarantee a finite action
completion deadline. Actual transitions are measured and deadlines checked; the
queue theorem remains valid during a stall regardless of action completion. This
does not prove the receiver's required transition deadline. The original open FIFO
eight-window campaign supplied neither enforced arrival limits nor a positive
service guarantee; its measured extrema have not been promoted to guarantees.

### Why this does not install into OVS/FRR

The current receiver schemas and drivers support OVS and Linux/FRR routing, not this
application FIFO operation. The FRR path has native qdisc endpoints and per-demand
counters, but these are measurement instruments, not traffic regulators or service
guarantees. A schema-valid hash/attestation on the FIFO must not be used to bless an
FRR executable plan. Exact runtime/namespace/queue/demand identities and causal
old/new transition guarantees are missing. The unchanged historical model runtime
qualification/equivalence requirements remain separate.

**No installation was generated and no receiver was exercised.** Results retain
`receiver_installable=false`, `trusted_installation=null`, `physical_qualified=false`
and `independent_attestation_accepted=false`. The acquisition producer cannot
self-sign an independent operator approval. A future FIFO-specific receiver would
need an approved exact driver/schema mapping, explicit operator/source review,
independent attestation and runtime ownership/deadline enforcement; this work does
not add a new execution runtime to bypass the current FRR gate.
