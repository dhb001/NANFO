# OpenAPI Documentation Standard

## Purpose
Define OpenAPI generation and documentation quality expectations.

## Scope
- Required endpoint documentation fields
- Example payload requirements
- Error response documentation
- Change management/versioning notes

## Dependency
- Response envelope requirements are defined in `API_STANDARD.md`.

## Schema source and generated client types (ADR-028)
- The schema is generated by the application (`app.openapi()`); `app.openapi()` works in
  every environment. The interactive `/api/docs`, `/api/redoc` and `/api/openapi.json`
  routes are served only when `APP_ENV` is not production (`API_DOCS_ENABLED` overrides),
  and the production gateway returns 404 for them.
- The frontend's contract types are generated from this schema into
  `frontend/src/shared/types/generated/openapi.ts` (`npm run api:types`). `npm run
  api:check` fails when the committed file drifts from the backend.
  `NANFO_OPENAPI_SCHEMA=<exported json>` uses a pre-exported schema. The generated file
  must be committed with backend contract changes.
- Every contract change must be listed in `ADR028-ContractChanges.md` (or its successor)
  with its BREAKING label, where the ADR assigns one.
